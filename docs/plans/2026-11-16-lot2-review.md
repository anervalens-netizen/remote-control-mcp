## Revised candidate shutdown finding

The [Codex review of `f9dd57e`](https://github.com/anervalens-netizen/remote-control-mcp/pull/55#discussion_r4592181907) found that closing only Fastify did not terminate an agent with a referenced live PTY handle. The development disposition is **fixed locally, awaiting the final source reviews and CI**. After awaited HTTP/onClose cleanup, the signal handler now exits the agent with its existing success/failure exit code. This restores process-exit behavior without adding process-tree termination or changing durable-job code.

Both SIGTERM and SIGINT were reproduced with a real child agent and a marked live PTY before the fix. The same scenarios now verify normal agent exit, clean aggregate publication, writer-claim release and the original fixture PTY no longer running. The fixture is Linux-specific because independent process identity checks use `/proc`. It does not claim termination of arbitrary descendants or shells that ignore hangup.
