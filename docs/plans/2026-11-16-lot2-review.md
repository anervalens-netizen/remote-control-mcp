## Revised candidate shutdown finding

The [Codex review of `f9dd57e`](https://github.com/anervalens-netizen/remote-control-mcp/pull/55#discussion_r4592181907) found that closing Fastify alone did not terminate an agent with a referenced live PTY handle. The intermediate `3033b09` correction added explicit process exit and passed both real SIGTERM/SIGINT PTY cases. That fixed the PTY finding but still allowed native threadpool teardown to wait indefinitely for a blocked FIFO read; the third review and subsequent correction below distinguish these paths.

The latest POSIX correction restores the requested stop signal after bounded cleanup and signals only the agent's own PID. A detected cleanup failure uses a distinct self-directed failure signal. The real Linux fixtures check the original marked PTY process and writer state. They do not certify arbitrary descendant termination, externally supplied native signal handlers or Windows FIFO behavior.
